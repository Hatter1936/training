# API Contract: Альпака Фин

**Base URL:** `http://localhost:8080/api`
**Статус:** В разработке

---

## 1. Общие соглашения

- **Формат данных:** JSON (`Content-Type: application/json`).
- **Кодировка:** UTF-8.
- **Даты и время:** например: `2026-10-24` - так правильно.
- **Булевы значения:** `true` / `false` (без кавычек).
- **Пустые значения:** Если поле необязательное, передаем `null` или не передаем ключ вообще.
- **Авторизация:** Передаём `userId` в query-параметрах или в теле запроса для простоты. Фронтенд сохраняет id, полученный при логине, в localStorage и передает его в параметре `?userId=` во всех защищенных запросах

### 2. Единый формат ошибок
Если бэкенд возвращает ошибку (400, 404, 500), она всегда приходит в таком виде:

```json
{
  "code": "ERROR_CODE",
  "message": "Понятное описание ошибки",
  "timestamp": "2026-10-22T12:00:00"
}
```

## Коды ответов:

- `200 OK` — Успешный GET, PATCH.
- `201 Created` — Успешный POST (создание).
- `204 No Content` — Успешный DELETE.
- `400 Bad Request` — Ошибка валидации.
- `404 Not Found` — Сущность не найдена.
- `500 Internal Server Error` — Ошибка на сервере.

## 3. Справочники (Enums)

- **Direction:** `INCOME` (поступление) | `EXPENSE` (списание)
- **Period:** `ONCE` (разово) | `MONTHLY`
- **Type (для Event)**: `INCOME` | `EXPENSE`

## 4. Эндпоинты (Ресурсы)

**БЛОК А: Авторизация и пользователи**

### 1. Регистрация
**Метод:** `POST /api/auth/register`

**Тело запроса:**

```json
{
  "email": "test@mail.ru",
  "password": "12345",
  "companyName": "ООО Ромашка"
}
```

**Ответ (201 Created):**

```json
{
"id": 1,
"email": "test@mail.ru",
"companyName": "ООО Ромашка"
}
```

**Ошибки:** `400 Bad Request` (если email уже занят).

### 2. Вход
**Метод:** `POST /api/auth/login`

**Тело запроса:**

```json
{
  "email": "test@mail.ru",
  "password": "12345"
}
```

**Ответ (200 OK):**

```json
{
"id": 1,
"email": "test@mail.ru",
"companyName": "ООО Ромашка"
}
```

**Ошибки:** `400 Bad Request` (неверный пароль).

**БЛОК Б: Транзакции (История операций)**

### 3. Загрузка выписки (CSV)
**Метод:** `POST /api/transactions/upload`

**Параметры (multipart/form-data):**
**file (файл CSV), userId (ID пользователя)**

**Ответ (200 OK):**

```json
{
  "importedCount": 150,
  "message": "Успешно загружено 150 операций"
}
```

**Ошибки:** `400 Bad Request` (неверный формат файла).

### 4. Получить список операций
**Метод:** `GET /api/transactions`

**Параметры (Query):**
`userId` (обязательно, например ?userId=1)
`dateFrom` (опционально, YYYY-MM-DD)
`categoryId` (опционально)

**Ответ (200 OK):**

```json
[
  {
    "id": 1,
    "operationDate": "2024-10-01",
    "amount": 990.00,
    "direction": "EXPENSE",
    "counterpartyName": "ПАО Банк",
    "paymentPurpose": "Комиссия за ведение счета",
    "categoryName": "Банковские услуги"
  }
]
```

### 5. Изменить категорию транзакции
**Метод:** `PATCH /api/transactions/{id}/category`

**Тело запроса:**

```json
{
"categoryId": 3
}
```

**Ответ (200 OK):** Обновленный объект транзакции.

**Ошибки:** `404 Not Found` (если транзакция не найдена).

**БЛОК В: События (Ручной ввод будущих платежей)**

### 6. Создать событие
**Метод:** `POST /api/events`

**Тело запроса:**

```json
{
  "userId": 1,
  "name": "Налог УСН",
  "type": "EXPENSE",
  "amount": 15000.00,
  "eventDate": "2026-11-28",
  "period": "MONTHLY"
}
```

**Ответ (201 Created):** Созданное событие с присвоенным id.
**Ошибки:** `400 Bad Request` (если сумма отрицательная).

### 7. Получить список событий
**Метод:** `GET /api/events`

**Параметры (Query):**
`userId` (обязательно, ?userId=1)

**Ответ (200 OK):** Массив объектов событий.

### 8. Отметить событие как "Оплачено"
**Метод:** `PATCH /api/events/{id}/pay`

**Ответ (200 OK):**

```json
{
  "id": 1,
  "isPaid": true
}
```

**Ошибки:** `404 Not Found`.
